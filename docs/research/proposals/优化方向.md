对。你现在需要的不是“一个最优方案”，而是建立一个 Bottleneck Distance optimization playground：把 GUDHI 的整个调用链拆成几十个可以独立替换、benchmark、回滚的模块。

对于当前阶段，我建议原则定成：

[
\boxed{\text{保持 exact 结果不变，允许实现方式疯狂变化}}
]

也就是所有优化先要求和

[
\texttt{gudhi.bottleneck_distance}(D_1,D_2,e=0)
]

严格对拍。先不要急着碰 approximate。

# 1. 把 Small-N 算法拆成 10 个优化层

整体是：

[
\boxed{
\text{Input}
\to
\text{Preprocess}
\to
\text{Bounds}
\to
\text{Candidate Radius}
\to
\text{Adjacency}
\to
\text{Initial Matching}
\to
\text{BFS}
\to
\text{DFS}
\to
\text{Memory}
\to
\text{Batch}
}
]

每一层都可以有多个替代实现。

我下面给你的是一个大约可以做 50–80 次实验的优化树。

---

# 2. 第一层：输入预处理

这部分单项收益一般小，但最容易做，而且 (M) 很大时会积少成多。

| 编号  | 优化                                    | 预期      |
| --- | ------------------------------------- | ------- |
| P1  | diagonal point 提前永久删除                 | 中       |
| P2  | finite / (+\infty) / (-\infty) 点只分类一次 | 中       |
| P3  | persistence (d-b) 预计算                 | 小       |
| P4  | diagonal distance ((d-b)/2) 预计算       | 中       |
| P5  | birth/death 改连续 `double[]`            | 小       |
| P6  | AoS → SoA                             | 值得测     |
| P7  | diagram point 数预存                     | 小       |
| P8  | max persistence 预存                    | 小       |
| P9  | essential-point count 预存              | 小       |
| P10 | diagram hash / identity cache         | 特定场景大   |
| P11 | 避免 Python list → ndarray 重复转换         | 中       |
| P12 | ndarray → C++ zero-copy view          | 中       |
| P13 | 固定 diagram 构造 reusable object         | 大量比较时中高 |
| P14 | 小 diagram stack storage               | 值得测     |
| P15 | 两个 diagram 自动把较小一侧设为搜索侧               | 值得测     |

尤其应该测试：

```text
RawDiagram
    ↓ preprocess once
PreparedDiagram
    births[]
    deaths[]
    persistence[]
    diagonal_distance[]
    essential data
```

以后 bottleneck 不接受“原始 diagram”，而接受 `PreparedDiagram`。

对于 one-to-many：

[
D_q\quad vs\quad D_1,\ldots,D_M
]

右边所有 preprocessing 全部只做一次。

# 3. 第二层：距离计算本身

Small-N 我认为这是一个大实验区。

当前最重要的候选：

### D1. 普通 double loop

直接：

[
C_{ij}
======

\max(|b_i-b_j|,|d_i-d_j|).
]

最朴素的两层循环。

不要小看它。对于 (n=10\sim50)，它可能非常强。

---

### D2. Dense distance matrix

一次产生：

[
C\in\mathbb R^{n\times m}.
]

后面所有 threshold decision 复用。

---

### D3. SoA distance kernel

不用：

```cpp
Point{x, y}
```

而是：

```cpp
birth1[]
death1[]

birth2[]
death2[]
```

减少结构体读取。

---

### D4. 手工 vectorization

连续计算：

[
|b_i-b_j|,
\qquad
|d_i-d_j|
]

再 `max`。

试：

* compiler auto-vectorization；
* AVX2；
* AVX-512，如果机器支持。

---

### D5. branchless distance

比较：

```cpp
max(abs(dx), abs(dy))
```

是否可以完全 branchless。

---

### D6. float distance matrix + double verification

这属于实验性：

先用 `float` 找 candidate，

最后用 double 验证。

如果要严格 exact，最终必须解决 rounding 问题，所以不优先。

---

### D7. 不存矩阵，on-demand 算

与 Dense Matrix 对拍：

[
\text{memory access}
\quad vs\quad
\text{recompute}.
]

Small-N 下计算太便宜，有可能：

> 重新算比读 cache matrix 还快。

这个必须 benchmark，不能预设 dense 一定赢。

---

# 4. 第三层：candidate distance 生成

GUDHI exact 的核心之一是产生 candidate radii。

这里可以试很多。

---

### C1. 原始全部生成 + `std::sort`

baseline。

---

### C2. 生成后 `unique`

Persistence diagrams 很可能有不少相同距离。

例如：

[
r_1,r_1,r_1,r_2,r_2,r_3.
]

变成：

[
r_1,r_2,r_3.
]

candidate decision 次数可能明显下降。

---

### C3. sort 时直接 deduplicate

减少额外 pass。

---

### C4. `std::sort` vs `pdqsort`

值得 benchmark。

---

### C5. TBB parallel sort

Small-N 大概率负优化。

但要测，尤其 (n) 接近中等规模时。

---

### C6. `nth_element`

不要一次排完全部距离。

如果 threshold search 本身类似 binary search：

[
\text{find median}
\rightarrow
\text{decision}
]

可以探索 selection-based algorithm。

---

### C7. Quickselect candidate search

不生成完整排序：

[
\operatorname{select}(k).
]

反复缩小区间。

这条算法性比较强。

---

### C8. Incremental edge sorting

直接建立：

```cpp
struct Edge {
    u;
    v;
    weight;
};
```

按 weight 排序。

然后：

[
e_1,e_2,\ldots
]

逐批激活。

---

### C9. 按 equal weight 分组激活

例如：

[
r=r_k
]

对应 7 条边。

一次全部激活，而不是一条一条。

---

### C10. candidate range clipping

先算：

[
L\le d_B\le U.
]

candidate 只保留：

[
r\in[L,U].
]

---

### C11. 先算 cheap UB 再生成 candidate

如果 UB 已很小，很多 cross-distance：

[
C_{ij}>U
]

根本没必要进入 candidate array。

---

### C12. fused distance + candidate generation

计算 (C_{ij}) 时直接：

```cpp
distance_matrix[i][j] = r;
candidates.push_back(r);
```

减少第二遍扫描。

# 5. 第四层：搜索 Bottleneck threshold

这其实可以形成一整个论文实验。

假设：

[
r_1<r_2<\cdots<r_K.
]

要找最小：

[
r_k:\operatorname{PerfectMatching}(r_k)=1.
]

可以比较很多搜索策略。

---

### T1. Binary search

最标准：

[
O(\log K)
]

次 decision。

---

### T2. GUDHI 当前 alpha-style search

作为 baseline。

---

### T3. interpolation search

如果距离分布比较均匀，可以估计：

[
k
\approx
K
\frac{r-L}{U-L}.
]

---

### T4. exponential search

如果实际 bottleneck 经常靠近 lower bound：

[
L,\quad
L+\Delta,\quad
L+2\Delta,\quad
L+4\Delta,\ldots
]

可能好用。

---

### T5. lower-bound-biased search

不要每次 midpoint。

比如：

[
k=
L+0.25(U-L).
]

你的数据如果 bottleneck 普遍较小，可能比 binary search 更好。

---

### T6. data-driven quantile search

根据历史 pair 的 bottleneck distribution。

例如第一次尝试 30% quantile candidate。

如果你的库长期处理相似数据，这可能有效。

---

### T7. incremental monotone search

我最看好之一：

[
r_1<r_2<r_3<\cdots
]

matching 只向前更新。

完全取消 rollback。

---

### T8. coarse-to-fine

先跳着测试：

[
r_1,r_4,r_8,\ldots
]

找到区间后局部搜索。

---

# 6. 第五层：cheap lower bounds

这部分既可用于缩小 exact 搜索区间，也可服务通用的 threshold-decision API。

### LB1

Diagonal radius：

[
a(D)=
\frac12\max_{p\in D}(d-b).
]

则：

[
|a(D_1)-a(D_2)|
\le d_B(D_1,D_2).
]

几乎免费。

---

### LB2. directed Hausdorff-to-diagram-or-diagonal

定义

[
h(D_1,D_2)
==========

\max_{p\in D_1}
\min\left(
d(p,\Delta),
\min_{q\in D_2}d_\infty(p,q)
\right).
]

则：

[
d_B(D_1,D_2)
\ge
\max(h(D_1,D_2),h(D_2,D_1)).
]

Dense matrix 已经有了的话非常便宜。

---

### LB3. bounding box

用：

[
\min b,\max b,\min d,\max d
]

产生非常便宜的必要条件。

单独可能弱，但成本很低。

---

### LB4. persistence range

最大 persistence 差异可以产生辅助 bound。

注意需要正确处理 diagonal matching，因此这个需要严格推导后再启用。

---

### LB5. pivot lower bound

已有：

[
d(x,y)
\ge
|d(x,p)-d(y,p)|.
]

---

### LB6. multi-pivot maximum

[
L(x,y)
======

\max_j
|d(x,p_j)-d(y,p_j)|.
]

---

### LB7. adaptive pivots

不是固定 8 个。

根据 candidate pool：

[
1\to2\to4\to8
]

逐步增加。

---

### LB8. cheap bound cascade

不要一次全算：

[
LB_1
\to
LB_2
\to
LB_3
\to
\text{exact}.
]

只对没剪掉的继续。

这个尤其值得做。

---

# 8. 第六层：threshold decision 的 cheap failure tests

这块有大量空间，而且比 BFS/DFS 更便宜。

给定 (r)，先不要马上跑 matching。

---

### F1. zero-degree test

如果某个 mandatory vertex：

[
\deg(v)=0
]

立即：

[
\text{fail}.
]

---

### F2. isolated mandatory count

直接检查。

---

### F3. degree-1 propagation

如果 mandatory vertex：

[
\deg(u)=1,
]

它可能形成 forced matching。

不断传播。

类似约束传播：

[
\deg 1
\rightarrow
match
\rightarrow
remove
\rightarrow
new\ \deg1.
]

非常值得试。

---

### F4. greedy maximal matching

正式 Hopcroft–Karp 前先跑超便宜 greedy。

Small-N 下经常可能直接得到 perfect matching。

---

### F5. smallest-degree-first greedy

而不是按 index：

[
u=\arg\min\deg(u).
]

---

### F6. nearest-edge-first greedy

---

### F7. persistence-priority greedy

优先处理不容易匹配 diagonal 的点。

---

### F8. connected-component test

threshold graph 如果分裂：

[
G=G_1\cup\cdots\cup G_s,
]

可以各 component 独立匹配。

---

### F9. component cardinality failure

某个 component 左右可匹配容量明显不够：

立即 fail。

---

### F10. 小规模 Hall checks

完整 Hall：

[
|N(S)|\ge |S|
]

太贵。

但可以只检查：

* singleton；
* pair；
* triple。

例如：

[
|N({u_i,u_j})|<2
]

立即 fail。

Small-N 可能很便宜。

这是一条非常值得实验的“小约束传播”路线。

# 13. 第十一层：bitset 这条线可以单独玩很久

Small-N 如果：

[
n\le64
]

我尤其建议把它作为独立专题。

表示：

[
N(u)\subseteq V
]

为：

```cpp
uint64_t adjacency[u];
```

于是：

邻居交：

[
N(u)\cap S
]

就是：

```cpp
adjacency[u] & S
```

删除：

```cpp
mask &= ~(1ULL << v);
```

判断是否为空：

```cpp
mask == 0
```

取第一个：

```cpp
countr_zero(mask)
```

删除第一个：

```cpp
mask &= mask - 1
```

计数：

```cpp
popcount(mask)
```

直接得到：

[
\deg(u).
]

由此可以顺手实现：

* degree-0 failure；
* degree-1 propagation；
* greedy；
* BFS；
* DFS；
* Hall pair tests；
* connected component；
* density estimation。

所以：

[
\boxed{\text{Small-N bitset kernel}}
]

我认为可以单独成为你的第一大实验分支。

甚至继续拆：

[
n\le32
]

```cpp
uint32_t
```

[
n\le64
]

```cpp
uint64_t
```

[
64<n\le128
]

两个 `uint64_t`。

看不同 specialization 是否值得。

# 16. 第十四层：matching 初始化顺序

这往往是被忽略的。

同一个算法，仅 vertex ordering 就可能差很多。

试：

[
\text{original order}
]

[
\text{random}
]

[
\text{degree ascending}
]

[
\text{degree descending}
]

[
\text{persistence descending}
]

[
\text{diagonal distance descending}
]

[
\text{nearest-neighbor distance ascending}
]

[
\text{distance-to-threshold margin ascending}.
]

我尤其看好：

[
\boxed{\text{最难匹配的 vertex 优先}}
]

也就是：

[
u
=

\arg\min \deg(u).
]

因为它类似 constraint satisfaction 里的 MRV：

[
\text{Minimum Remaining Values}.
]

这是一个非常便宜的启发式。

# 17. 第十五层：constraint propagation

这是一条可以独立研究的算法路线。

在真正跑 matching 前不断做：

[
\deg(u)=0
\Rightarrow fail
]

[
\deg(u)=1
\Rightarrow forced
]

然后删除对应 vertex。

继续：

[
\deg(u')\downarrow.
]

有点类似 SAT / exact cover preprocessing。

还可以继续试：

### CP1

single vertex forced。

### CP2

pair Hall condition。

如果两个 U：

[
|N(u_1)\cup N(u_2)|=2
]

那么这两个 V 形成一个受限块。

### CP3

triple Hall condition。

### CP4

component decomposition。

### CP5

dominated neighbor sets。

如果：

[
N(u_1)\subseteq N(u_2),
]

优先处理 (u_1)。

这类优化特别有“算法味”，而不只是工程 micro-optimization。

# 18. 第十六层：利用 threshold 单调性

这是另一个非常大的实验树。

因为：

[
r_1<r_2
\Rightarrow
E(r_1)\subseteq E(r_2).
]

所以可以缓存：

### I1

matching。

### I2

adjacency。

### I3

vertex degree。

### I4

connected components。

### I5

unmatched set。

### I6

edge activation pointer。

### I7

neighbor bitset。

### I8

greedy result。

也就是说：

```text
r = r1
match

add edges

r = r2
continue match

add edges

r = r3
continue match
```

而不是：

```text
r1 -> reconstruct
r2 -> reconstruct
r3 -> reconstruct
```

# 19. 第十七层：直接改变 Bottleneck exact 算法

这些风险更高，但值得长期试。

### R1. incremental perfect matching

前面说过。

我很推荐。

---

### R2. offline edge activation

所有 edge：

[
e_1,\ldots,e_K
]

按 weight 排好。

匹配状态增量维护。

---

### R3. parallel binary search

对于同一个 query 同时算很多 diagrams：

[
D_q\leftrightarrow D_i.
]

多个 pair 可以一起按 candidate threshold 分桶 decision。

比较复杂，但有研究价值。

---

### R4. mandatory-vertex formulation

不要显式创建所有 diagonal projection vertices。

给定 (r)：

[
\frac{d-b}{2}>r
]

的点必须 cross-match。

其余点允许 diagonal。

把问题直接写成 partial matching coverage。

如果正确实现，有可能：

[
|V|
]

直接下降很多。

这条我认为很值得做数学证明。

---

### R5. component bottleneck

如果几何 graph 在某个 upper bound 内已经天然分块：

每个 block 独立计算 bottleneck，

最终：

[
d_B=\max_i d_B^{(i)}.
]

要严格证明 decomposition 条件。

# 21. 通用 threshold-decision API

除了返回 exact 距离，标准库可以提供一个独立判定能力：

[
\operatorname{within}(D_1,D_2,\tau)
\Longleftrightarrow
d_B(D_1,D_2)\le\tau.
]

如果 lower bound 已经满足：

[
LB>\tau,
]

可以直接返回 false；否则只需判断：

[
\operatorname{PerfectMatching}(G_\tau).
]

调用方只需要布尔结果时，不必先求完整 exact 距离。该能力应具有明确的等号、无穷点和异常输入语义，并与 exact API 逐例对拍。

可以比较：

* direct decision；
* LB + decision；
* multiple bounds + decision；
* prepared diagram + decision；
* batch decision。

# 22. 批量任务调度顺序

one-to-many 和 many-to-many 的结果不应依赖任务顺序，但执行顺序会影响负载均衡、缓存局部性和尾部延迟。

可以比较：

### O1

保持输入顺序。

### O2

按 diagram point count 分桶。

### O3

按预估 adjacency density 分桶。

### O4

按 prepared diagram 的内存局部性分块。

### O5

按预估成本做 longest-processing-time-first 调度。

排序或分桶本身有成本，所以应该按 (M) 分区 benchmark：

[
M=20,100,1000,10000.
]

很可能 Small-(M) 负优化，Large-(M) 正优化。

# 23. 不要只按 n 做 benchmark

我建议建立 4 维 benchmark grid：

[
(n,m,\rho,M)
]

其中：

[
n=|D_1|,
\quad
m=|D_2|,
]

[
\rho=
\frac{E(r^*)}{nm},
]

[
M=\text{pair count}.
]

测试：

[
n,m\in
{4,8,16,32,64,128,256}.
]

再分：

[
\rho\in
{\text{sparse},\text{medium},\text{dense}}.
]

因为：

> 同样 (n=64)，一个只有几十条 edge 的 graph 和一个接近 complete bipartite graph，最佳算法完全可能不同。

# 24. 最后可以得到一个真正的 adaptive dispatcher

不要追求一个算法打天下。

最终很可能是：

[
\boxed{
\operatorname{solver}(n,\rho,K)
}
]

例如实验后可能得到：

[
n\le 16
\Rightarrow
\text{Kuhn + uint32}
]

[
16<n\le64,\rho>0.3
\Rightarrow
\text{uint64 bitset HK}
]

[
16<n\le64,\rho<0.3
\Rightarrow
\text{sparse adjacency Kuhn/HK}
]

[
64<n<200
\Rightarrow
\text{SIMD linear neighbor scan}
]

[
n\ge200
\Rightarrow
\text{KD-tree / Hera style}.
]

这比追求一个固定的：

> “我的 Bottleneck 算法”

合理很多。
